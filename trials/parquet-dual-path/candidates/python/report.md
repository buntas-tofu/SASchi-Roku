# Python dual-path interchange trial

Status: executed engineering observations for the frozen packet, not general SAS fidelity or live-SAS proof. Maintainers may use these results to review this converter. The evidence covers five supplied envelopes, two pinned SAS datasets with one tested both with and without its catalog, and a generated byte/tag stress case. Different sources, library versions or policies require fresh validation.

The implementation is `convert.py`. Invoke it with the supplied Python runtime:

```text
/tmp/roku-interchange-runtime/bin/python output/convert.py convert INPUT NEW_OUTPUT_DIRECTORY [--catalog CATALOG]
/tmp/roku-interchange-runtime/bin/python output/convert.py validate INPUT OUTPUT_DIRECTORY [--catalog CATALOG]
```

`CONTRACT.md` remains unchanged. Delivered code performs no network access, installation, program translation or R bridge. It detects the admitted envelope representation from content rather than case names. It refuses existing destinations. Every envelope descriptor and cell is checked, and both projections are built, before a destination is created. Conversion reopens and validates its own outputs. A failed conversion removes its newly created directory.

## Preservation boundaries

The retained source is the original-byte archival boundary. Each conversion copies the exact data input into `source/INPUT_BASENAME`, adds the supplied catalog, and retains a sibling LICENSE when present. Ordered role/path/SHA-256 entries bind all retained files. The pinned SAS fixture identities and LICENSE matched every supplied manifest digest. The fixture notice identifies Apache-2.0 licensing and the bundled ReadStat MIT notice. The runtime copies retain that LICENSE; no upstream binary or generated dataset is included in this code delivery.

Archive Parquet is a separate projection. Envelope character cells contain lowercase hex of the exact supplied complete physical bytes, including padding and undecodable bytes. SAS character cells contain lowercase hex of UTF-8 re-encoded reader strings, explicitly labeled `reader-utf8-reencoding`. This is reversible to reader strings, not recovered SAS character storage or padding. Original SAS bytes remain available only in the retained SAS file. Successful reader decoding does not promote that projection to original-byte preservation.

Each table starts with int64 `__row_index`, zero-based in source order. Duplicate identifiers stay duplicates. Numeric archive fields are float64 in SAS units, followed immediately by string missing-tag fields. Finite numeric cells have an empty tag; null cells retain their canonical marker, including ordinary `.`, `._`, and `.A` through `.Z`.

Analysis converts every numeric missing marker to null and records its marker and exact row/column event. Character bytes use strict declared-codec decoding for envelopes and UTF-8 for SAS reader strings. NUL has precedence and becomes null with `embedded-nul`; decoding failure becomes null with `decode-error`; ASCII-space-only right trimming yields `blank-to-null` or `right-trim`. Leading space, literal NA, quotes, commas, CR/LF, tabs and valid Unicode survive. Undefined CP1252 bytes never become replacement characters. Events are row-major, source-column ordered, one event per affected cell.

## Types and descriptors

Declared dates use the SAS 1960-01-01 origin and become date32; declared datetimes become timestamp microseconds without a timezone. Time stays float64 seconds. Archive values retain their original numeric SAS units. Fractional dates are rejected because date32 cannot represent them exactly. Datetimes round once to nearest microsecond using decimal rendering of the reader float and half-even ties, then add an integer epoch offset. The supplied finite datetime witnesses are exactly representable at microsecond precision; arbitrary submicrosecond inputs were not tested. Representational overflow is rejected.

The SAS format profile explicitly recognizes DATE and YYMMDD, optionally with width, plus DATETIME and TIME, optionally with width/decimal precision. Recognition is case-insensitive. Other numeric formats stay numeric. This is an explicit bounded interpretation, not inference from values or column names. The supplied SAS profile exercised YYMMDD10, DATETIME and TIME20.3. Metadata records this profile, source origin, units and timezone null. A consumer's display timezone is not source evidence.

Ordered descriptors preserve names, kinds, logical types, declared or reader-exposed source widths, labels, formats, informats and value labels. pyreadstat 1.3.7 exposes `variable_storage_width` and `original_variable_informats` for both supplied datasets, so their informats are retained rather than reported unavailable. Source encoding comes from the envelope or reader metadata. No width or encoding is inferred from observed strings. Descriptor labels in the actual SAS files were null; non-null SAS variable labels and a character-label catalog were not tested. The envelope descriptors exercise non-null labels and a numeric value-label mapping.

SAS data are read with `user_missing=True` and datetime conversion disabled. Catalogs are read separately and joined through the reader's variable-to-format metadata, preserving stored numeric codes. The supplied catalog's tagged key is canonicalized to `.A` with its text retained. Without a supplied catalog, value labels remain null and catalog status is absent. A provided catalog status means a catalog was supplied and parsed; it does not claim every catalog has a matching format. Unavailable properties remain null and gaps are explained. No original SAS file rewrite is claimed.

## Identity and validation evidence

Both Parquet schemas contain the input SHA-256, optional catalog SHA-256, mode and schema version string bindings. `metadata.json` binds ordered descriptors, per-cell events, retained source identity, both output hashes and library versions. `validate` reconstructs the entire expected typed projection from the external source and supplied catalog; it then reopens both written files, compares complete ordered Arrow schemas and values, and checks finite float64 payloads including signed zero. It compares all metadata against that reconstruction and current output hashes, then checks retained source copies against external-source hashes. Hashes alone cannot make altered values pass. Validation performs no writes.

The final executed self-test completed 49 CLI assertions. These included successful conversion and complete validation for all five envelopes; sample SAS; missing SAS without catalog; missing SAS with catalog; content-based renamed inputs; and a generated 256-cell CP1252 byte matrix covering all 28 canonical numeric missing tags. The envelope value checks use independent datetime arithmetic from the original 1960 origin, exact hex comparison, strict decoding and missing-tag comparison. SAS checks compare descriptors, catalog label mappings and each archive cell against a fresh pyreadstat read. That fresh read shares ReadStat and is not independent SAS proof.

Negative checks rejected existing destinations unchanged; changed/reordered values after output-hash updates; collapsed tags after rehashing; wrong date values after rehashing; binary corruption; a changed retained source; wrong external source; swapped/stale metadata; missing events; altered schema bindings; omitted/wrong catalogs; reserved/duplicate names; malformed or wrong-width hex; invalid missing tags; boolean/ambiguous numeric cells; fractional dates; and an unknown codec. Validation tests took before/after tree digests and confirmed no modifications. Invalid envelopes left no output directories.

Native R independently reopened all eight supplied-fixture Parquet pairs and checked row counts, every field type, leading int64 row identity type and mode bindings. This R check established cross-consumer transport and schema readability, not a full independent R value oracle. The parent evaluator's separate checks have not been seen or claimed. No live SAS runtime exists in this trial.

Runtime evidence: Python 3.12.16, pyarrow 25.0.1 and pyreadstat 1.3.7. pandas 3.1.0 is installed but is not used by the converter. The R consumption test used R 4.4.3, arrow 25.0.1 and jsonlite 2.0.0; haven 2.5.5 was installed but not used by that test. Underlying ReadStat build revision and model revision/settings were not exposed. Validation currently requires the recorded Python/library versions to equal its runtime, so library upgrades require reconversion or a separately designed migration policy. This is an in-memory bounded converter, not a large-data streaming benchmark, a metadata digital signature, or support for arbitrary SAS formats/catalogs.

The unchanged project linter passed on code before report generation. The final full-output linter command and result are recorded in `history.md`. Temporary test directories and generated data were removed before delivery.
